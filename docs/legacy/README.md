# Legacy Documentation (Archived)

> **ARCHIVED — nothing in this folder is maintained, and any of it may be wrong.**
> These are the hand-written feature write-ups that used to sit at the repository root. They were
> written while the features were being built, they were never revised afterwards, and they have
> been superseded. The current, source-verified documentation is
> [`../external/`](../external/README.md) and [`../internal/`](../internal/README.md) — start there.
> **Do not trust a single statement in this folder without checking it against the code at `HEAD`.**
> These files are not a second opinion; where one of them disagrees with `external/` or `internal/`,
> the current docs and the Java source are right and the legacy file is stale. They are stale even
> against themselves: `PHYSICAL_MEDIA_FEATURE.md` §2.5 asserts that the Excel importer dedupes on
> `(physical_media_type, physical_label)`, its own §6 says there is no dedupe at all, and the code
> agrees with §6 — the importer is insert-only.

**Audience:** anyone tracing why the backend works the way it does ·
**Scope:** `docs/legacy/` · **Status:** frozen, kept verbatim, superseded

Nine documents live here. Each one owned some ground that a page under
[`../external/`](../external/README.md) or [`../internal/`](../internal/README.md) now owns properly,
rewritten from the Java source rather than carried over. Everything in them still true and still
useful was folded into those pages before they were moved here. What is left is the part that a
reference page cannot hold: the reasoning behind a design, the state of the world on the day a
feature shipped, a roadmap that was never built, and a frontend walkthrough written for a specific
audience at a specific moment.

## Why these were kept rather than deleted

The current documentation records what the backend does; these files record why it was built that
way, and that reasoning is not recoverable from the source — nothing in the code explains the threat
model behind proxying media bytes, the workbook census behind the physical-media inventory, or the
choice to cap a maqam panel at three teachers. Several also carry material that has no home in a
reference page at all: an OpenAPI 3.1 specification, a Phase 2 roadmap that was never implemented,
and frontend integration walkthroughs written for a particular audience on a particular day.
Deleting them would trade a small amount of clutter for the loss of the project's only design
record, so they are frozen and clearly marked instead.
